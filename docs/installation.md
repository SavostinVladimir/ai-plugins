# Установка, обновление и восстановление

## Первый запуск

Нужен Python 3.11+. Выполните list и plan из README. Выберите один пакет либо настройте именованный экземпляр. Не используйте файл examples как реальные
пути без адаптации. Registry не является общим переносимым конфигом: у каждой
машины и экземпляра свои пути и state.

## Миграция ручной установки

Старая ручная версия spec-review находится вне управления менеджера. Plan покажет
существующие файлы и, при наличии, unmarked-правило в глобальных инструкциях.

1. Сохраните копию старых файлов и глобальных инструкций.
2. Сравните план с текущей версией. При переносе навыка из ~/.codex/skills в
   ~/.agents/skills учтите существующую ссылку: не оставляйте две расходящиеся копии.
3. Осознанно удалите только старый блок автоматического запуска из глобальных
   инструкций или вручную приведите его к новому управляемому блоку и registry
   через установку. Не удаляйте весь AGENTS.md. Простое создание tracked
   marker вручную без registry не означает adoption и будет конфликтом.
4. Установите через `install spec-review --adopt` с выбранными экземпляром.
   Payload-оригиналы сохраняются для uninstall; остальные инструкции сохраняются.

По умолчанию установщик не удаляет старую копию навыка в другом каталоге. Перенос
между каталогами — отдельное осознанное действие, чтобы не удалить чужой навык.
На чистой машине миграция не нужна.

## Обновление

`git pull --ff-only`, затем `status` и `update spec-review` либо `update --installed`.
Все команды используют одинаковые --config/--instance и пути. Для проверки без
записи используйте `update --installed --dry-run`. Только установленные пакеты
выбираются --installed; они должны присутствовать в текущем каталоге исходников.
При смене release tag установленная версия остаётся до явного update, включая
переход на предыдущую версию. Изменённые вручную файлы блокируют обновление.
Модель лучше менять в локальном TOML или флагом, а не в сгенерированном файле.

## Сбои и резервные копии

`state-path/installed.json` хранит версии, хеши, оригиналы и локальные overrides.
`state-path/backups/*.json` содержит снимок затронутых файлов перед операцией:
ключ — абсолютный путь, значение — исходные байты в base64, null — файла не было.
Обычная ошибка записи вызывает откат. При crash/power loss проверьте journal,
остановите другие операции и восстановите нужные файлы из снимка; null означает
удаление только файла этой операции. Не запускайте старый journal вслепую после
новых пользовательских изменений. Резервные копии могут содержать глобальные
инструкции пользователя: храните state приватно, не коммитьте его в репозиторий.

`mutation.lock` исключает одновременную работу менеджеров с одним state. При
оставшемся lock сначала проверьте, что процесс с указанным PID уже не работает,
и лишь затем удалите lock вручную. Менеджер не снимает чужой lock автоматически.

Uninstall проверяет целостность, удаляет свои неизменённые payload и блок правил,
восстанавливает оригиналы, сохраняет посторонний текст, backups и registry.
При ручном drift сперва сохраните изменения и согласуйте содержимое с записью
registry; --adopt этот конфликт не обходит.
