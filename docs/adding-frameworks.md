# Добавление пакета Codex

Создайте frameworks/<id> с уникальным идентификатором из строчных букв, цифр и дефисов.
Минимальный manifest.toml:

```toml
id = "example-review"
version = "1.0.0"
name = "Example review"
description = "A Codex workflow"
```

Если пакету нужны собственные роли, добавьте agents/*.toml. Пакет может содержать
только навык, без каталога agents/; в плане его models будет пустым объектом.
Имя файла роли совпадает с name внутри, имена ролей уникальны
между пакетами. В каждом файле укажите name, description, model,
model_reasoning_effort (при необходимости), developer_instructions. Это обычные
нативные агенты Codex; установщик не генерирует им промпты и модели.

Добавьте skills/<id>/SKILL.md и необходимые assets/метаданные. Имя установленного
навыка совпадает с пакетом. В SKILL.md допустим маркер {{agents_path}} для каталога
агентов, заданного при установке. Остальные файлы копируются как есть.

В instructions.md поместите короткое правило автоматического запуска.
{{invocation}} заменяется на $<id>. Оно устанавливается управляемым блоком в
глобальные инструкции и не заменяет весь AGENTS.md.

Добавьте фикстуры запроса, дефектной/корректной спеки, источников и ожидаемых
замечаний. Ожидания предназначены координатору и не передаются независимым ролям.
Повышайте версию manifest при выпуске изменений. Проверьте unittest, plan и
временный цикл install/check/update/uninstall. Затем отдельно проверьте реальный
запуск в Codex. Новые пакеты не устанавливаются автоматически через update --installed.
